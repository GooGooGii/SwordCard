# 出牌手感全面評估 — FEEL-001

2026-10-05，Codex。評估對象是正式 Three.js 網頁版，不套用 SwordCard/Godot 舊版操作規則。本輪只交付評估、重現工具與協作排程，尚未改正式玩法或部署。優先順序依目前程式與隔離瀏覽器觀察判定；下列時間／距離是候選設計值，需手機試玩校準。

目前最值得做的是：先修拖曳與錯誤防護，再加入唯一合法目標快出、容易命中的目標區，以及縮短演出後不能操作的空檔。直接把所有牌改成單點立即打出，會讓手牌檢視和誤觸問題變大。

## 已確認的現況

| 證據 | 結果／影響 |
|---|---|
| 正式建置，隔離存檔，唯一合法敵人，卡片「劍招」 | 第一次點選、第二次取消，兩次後仍 8 張手牌。單體牌沒有同卡第二次點擊確認或唯一敵人自動指定。 |
| 未預選直接拖至敵人 | 0 個 active drop zone；敵人落點 pointer-events:none；放開後牌仍在手上。選敵高亮依 selected/hover 啟用，但 hover 判定本身需要能命中的落點，形成循環。 |
| 拖曳時 computed transform | 桌機為 hover 的 scale(1.06)、Y=-38.4，而不是手指／游標位移。ui.css 的 :hover !important 蓋過 inline 拖曳 transform。 |
| 先選牌再拖到敵人 | 落點變為 active，重現中可打出，手牌由 8→7；但牌的視覺 transform 仍被 hover 蓋住。這是不同於核心傷害或隨機失敗的互動問題。 |
| Hand 的 tryPlay 與 BattleScreen 的 onTargetClick | 拖放會檢查 canPlay，點擊目標路徑沒有同一層合法性防護。真氣不足或對昏迷隊友用普通治療等操作可能讓 playCard 拋例外。此項是源碼確認，未在本輪誘發使用者實機例外。 |
| Hand / BattleScreen 的卡牌定義 | Hand 用 effectiveCard，selectedKind 用原始 cardDef。角色倒下轉成「心念」時，卡面與選敵模式可能不一致。源碼確認。 |
| 固定操作值 | 長按 450ms、點擊位移門檻 8px、自身／全體牌上拖門檻 110px。手機 390px 高的畫面中，110px 約占高度 28%，且未隨手牌邊界調整。 |
| 動畫鎖 | 1× 簡單單次攻擊時序約 330+170+200=700ms；多段／多效果逐拍相加，期间 busy 阻止出下一張。這是程式排程估算，不是手機輸入延遲實測。現有設定已有 1×／1.5×／略過。 |
| 預覽 | 已有傷害／護體／剋抗／連鎖預覽、長按放大和受擊數字，不需要再重做一套。尚缺目標扣血後結果、治療溢補與明確可出牌提示。 |

重現：[桌機 report](previews/card-feel-audit/report.json)、[手機 CDP 觸控 report](previews/card-feel-audit-mobile/report.json)。手機是 Chromium 844×390 觸控模擬，不是實體機測量。工具：tools/qa/card-feel-audit.mjs。原存檔與線上站點沒有被修改。

## 目標規格：自動指定何時安全

候選目標必須以 **effectiveCard + 最新戰鬥狀態 + canPlay** 計算，不能只看畫面上剩幾張肖像。

| 情境 | 建議行為 |
|---|---|
| 單體敵方牌，只有 1 個合法目標 | 自動指定；短上滑／同卡再次確認直接出，不需要再去點敵人。快出模式可用短點立即出。 |
| 單體敌方牌，2 個以上合法目標 | 選卡後點目標，或拖曳瞄準；顯示清楚的準星／箭頭。保留真正的策略選擇。 |
| 自身／全體／無目標牌 | 上推跨出手牌區即可出；全體牌高亮所有受影響單位。快出模式可短點立即出。 |
| 隊友牌，只有 1 個合法隊友 | 同樣自動指定，但治療、護體、復活各自按實際規則判定。 |
| 只有 1 名隊友受傷／昏迷，其他隊友還是合法目標 | 可推薦受傷／昏迷者，不偷偷直接施放；「唯一有收益」不等於「唯一合法」。目前復活牌對活人也能治療，不能擅自限定只選昏迷者。 |
| 頭目 + 血池／水域等可攻擊場地 | 仍有 2 個合法目標。普通單體攻擊可打場地，而全體攻擊的範圍又可能不含場地；不能把 aliveEnemies 預設排除場地的結果當自動選敵清單。明示「攻擊頭目／破除場地」。 |
| 真氣不足／合擊條件不符／已結束／沒有合法目標 | 不出、不扣資源，立即顯示原因。沒有合法目標不能自動選陣列第 0 個。 |
| 拖曳中目標死亡／召喚替換／隊員狀態改變 | 放開時再次驗證 UID 與合法性；失效則取消並說明，不自動打到新召喚的另一個敵人。 |
| 心念、升級牌、變動費用 | 必須使用當下有效卡牌定义與費用，卡面、合法目標、提示、最後結算一致。 |

## 所有主要優化面與取捨

工量「小／中／大」是相對改動規模，不是天數承諾。P0 必修；P1 首批；P2 試玩後加；P3 暫不採用。

| # | 方案 | 收益 | 風險／設計邊界 | 優先／工量 |
|---|---|---|---|---|
| 01 | 拖曳開始立即啟用所有合法落點 | 解決先選牌才拖得出去 | 落點只做命中，不攔截菜單與手牌 | P0／中 |
| 02 | 拖曳取消 hover 動畫與 CSS transition | 卡片真正跟手，沒有尾追延遲 | hover 僅限精確滑鼠；移動用 RAF/ref，選牌用 state | P0／小 |
| 03 | 拖曳影像避開 elementFromPoint 命中 | 防止修完跟手後，卡片自己蓋住目標 | 用獨立 pointer-events:none ghost 或幾何命中；原 capture 節點保持穩定。此是待修版本需防的新風險，不是本輪已重現缺陷 | P0／中 |
| 04 | 統一合法目標與 canPlay 防護 | 所有點／拖／鍵盤使用同一規則 | 指向最新狀態，防重入及重複 uid 出牌 | P0／中 |
| 05 | 唯一合法目標自動指定 | 去掉不必要的瞄準 | 包含場地與特殊隊友規則，不偷替玩家選擇 | P1／小 |
| 06 | 自身／全體牌用手牌區邊界出牌 | 省力、手機不必拉 110px | 以越界距離＋清楚的「放開出牌」區為準，保留回拖取消 | P1／中 |
| 07 | 唯一目標同卡第二次點確認 | 修正現在二點只是取消，手指不用移到敵人 | 點空白／向下滑另做取消，保持檢視操作 | P1／小 |
| 08 | 可選單點快出模式 | 唯一目標／無目標牌可一點出 | 手牌重疊時誤觸與無法閱讀；先做選項，長按純預覽，只有 pointerup 才派發 | P2／中 |
| 09 | 多目標「點卡→點敵」與拖曳並存 | 精準拖拉能力不足也能玩 | 一次選牌、一個目標點擊，不加第三次確認 | P1／小 |
| 10 | 擴大命中區與最近合法目標吸附 | 不必戳中小人物，手指更自然 | 建議額外 24–40 CSS px，最近中心＋遲滯；拒絕超遠投放，不遮 UI | P1／中 |
| 11 | 目標切換遲滯與黏附 | 敵人相近時準星不跳動 | 不能跨過使用者明確選中的目標；取消時清乾淨 | P1／中 |
| 12 | 瞄準線／目標輪廓／出牌區 | 按下到放開的結果可預知 | 準星放在手指上方；區分可出、無效、取消 | P1／中 |
| 13 | 拖曳門檻按裝置校準 | 手指微抖不被當成拖曳 | 手機候選 12–16px、滑鼠 6–8px；實機測試後定，避免直接減到 0 | P1／小 |
| 14 | 按壓／長按／拖曳明確狀態機 | 長按看完不會誤出，多指不打亂 | pointercancel、lostcapture、切背景、禁用／卸載全取消；使用放開坐標而非過期 dy | P0／中 |
| 15 | 取消與無效投放回彈 | 明確知道「這張沒出」 | 回彈 120–180ms 候選；不讓回彈擋下一次選牌 | P1／小 |
| 16 | 點空白／Esc／下滑取消 | 選错牌容易回復 | 必須與出牌上滑門檻分開，不能點卡確認同時取消 | P1／小 |

| 18 | 治療／復活／溢補與全體預覽 | 藥品更容易選人 | 無收益只提示，不把合法出牌硬禁止；不暗改規則 | P1／中 |
| 19 | 真氣與合擊／自損／耗盡預覽 | 出之前知道代價 | 消耗與結束回合牌標記突出；不為每張卡加確認窗 | P1／中 |
| 20 | 放大卡片與手牌重排 | 手機文字不被遮，牌少时更容易拿 | 選牌浮起時保留其他牌入口，不在手指下面顯示細字 | P1／中 |
| 21 | 無效原因即时短訊息 | 「按了沒反應」變為知道原因 | 例如真氣不足／角色昏迷／合擊條件；不每次弹 modal | P1／小 |
| 22 | 立即收牌／費用與輕音效回饋 | 知道輸入已接受，減少狂點 | 接受回饋可即時，實際 HP 仍在命中時更新；UID 防重複 | P1／中 |

| 24 | 動畫期間允許看／選下一張 | 移除手牌完全僵住的感覺 | 可以預選，不立即再結算；前一張抽牌後 uid 消失要取消 | P1／中 |

| 28 | 結束回合只在仍有可打牌時提醒 | 防止把剩餘真氣按掉 | 不是強制每回合再按；免費牌／道具也須考慮；警示不倒數自動結束 | P1／中 |

| 32 | 將手牌移動從 React 每次重绘改為 RAF | 拖曳低延遲，預覽只在目標變動時算 | 在低畫質＋三角色／多敵人實測；不先加复杂采样库 | P1／中 |
| 33 | 自動挑最低血敵人／替玩家挑治療對象 | 看似更快 | 改變策略，錯打場地／錯補人。只提供推薦高亮，不自動派發 | P3／不作預設 |
| 34 | 開放無限制排牌／直接同時結算所有動畫 | 高速連打 | 真氣、抽牌、擊殺、召喚、phase、連鎖、存檔會不一致。先用單張缓冲，禁止無限制方案 | P3／不採用 |
| 35 | 所有牌單點即出／長按當出牌／速甩即發 | 看似減少操作 | 誤觸、閱讀与取消衝突；長按必須純檢視，速甩放 P2 個別試驗，不直接当唯一預設 | P3／不作唯一預設 |

拖曳應保留點選替代，並提供足夠大的觸控入口。這與 [W3C 拖曳替代操作](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) 的方向一致；本案 48px 是自訂手機目標，不冒充 [WCAG 2.2 的 24px 最低規則與間距例外](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)。

## 建議採用的首批操作

1. 點一次卡：浮起、讀完整效果與當前費用；長按只看，不出。
2. 唯一合法目標／無目標：短上滑跨出手牌區，放開即出；或同卡點第二次直接出，不再點敵人。
3. 多目標：拖到吸附區放開，或選卡後點敵人／隊友。吸附只提高容錯，不幫忙挑戰術目標。
4. 回拖到手牌區／下滑／點空白：取消。真氣不足時立即說明，牌不扣、不消失。
5. 命中／收牌後可先選下一張，縮短純裝飾等待；真正連續派發留待單張缓冲階段。
6. 熟悉後可以開「單點快出」：僅限唯一合法目標或無目標牌。讀牌仍能長按，危險牌標記保留。

這套預設會先降低瞄準負擔、修掉失敗操作，也保留手機閱讀時間。「單點立即出」更快，但適合作為可選模式試玩比較。

## 落地順序與驗收

| 任務 | 內容 | 驗收 |
|---|---|---|
| FEEL-002，P0 | 狀態機／命中啟用／hover 衝突／中央防護／effectiveCard一致 | 桌機與手機未預選直接拖曳成功；卡片視覺跟手；取消、長按、斷觸都不出；非法點擊無例外、無資源消耗；每 UID 最多一次。 |
| FEEL-003，P1 | 唯一合法目標／無目標快出、同卡確認、吸附與取消 | 1 敵、2 敵、敵+場地、唯一隊友、普通治療、復活對活人、心念、零費／免費牌、真氣不足、抽牌／召喚後目標重新驗證。 |
| FEEL-004，P1 | 預覽、按壓／失敗回饋、手牌可讀性、演出等待縮短 | 預測與 core 一致；高／低畫質、大小手機、滿 8–10 手牌、三人隊、多遺物；非關鍵音效與效果不擋後續選牌。 |
| FEEL-005，P2 | 單點快出、單張缓冲、觸覺／快捷鍵／左右手 | 對比試玩，不隱藏失败；勝利、換階段、抽牌、目標 UID 替换時佇列安全取消；手機不支援震動也照常玩。 |

記錄出牌所需手勢數、接受回饋時間、拖曳成功率／重試率、誤出率、取消成功率、低畫質幀時間與命中後可選下一張的時間。候選目標：手勢 1–2 次；輸入後下一幀顯示接受／拒絕；跟手 transform 無 140ms transition；非動畫核心的尾段盡量不鎖操作。數值待實機測量，不宣稱現已達成。
