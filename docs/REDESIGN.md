## 0. 為什麼重做

舊 SwordCard 是 4.5 個月、692 次提交、3.9 萬行 GDScript 的產物，四個問題都出在根本：

1. **類型錯位**：仙劍一的魅力在故事與人，《殺戮尖塔》式的隨機地圖與可重玩 run 反而把故事稀釋掉。
2. **系統膨脹**：主備制組隊、37 種藥、56 件遺物、A0–A20、多敵、召喚、變身、圖鑑、成就、每日挑戰……每個系統都只調到一半，彼此交互就生出 bug。
3. **美術沒有統一的畫風**：寫實厚塗背景、水彩卡圖、水墨立繪、3D 草模並存。
4. **架構失控**：`main.gd` 一個檔 1.2 萬行，UI 全用程式碼硬拼。

## 1. 定位與支柱

> **一部可以玩的仙劍一：用卡牌戰鬥，重走餘杭到南詔的那段路。**

- 類型：章節式敘事卡牌 RPG。主線約 4–6 小時。
- 平台：瀏覽器直接玩；另外打包成 Android App 與 Windows 程式。橫向畫面。
- 這是私人同人作品：仙劍 IP 屬於大宇，**不公開散佈，不營利**。
  - 網址只私下分享，要加存取控制（密碼或白名單）並禁止搜尋引擎收錄。
  - 雲端建模服務只用私有模式（例如 Tripo 免費方案產出的模型是公開的，不能用）。

三根支柱。新增任何內容前先問「踩哪根支柱」；一根都沒踩到的不做。

1. **每場仗都有劇情理由**：夥伴依正史加入、離開，離開時要讓玩家真的難過。
2. **戰鬥是可讀的小謎題**：勝負來自五靈相剋與出牌順序，而不是堆數值。沒有命中率、暴擊或傷害浮動；隨機只出現在抽牌與獎勵。卡面即時顯示最終數字，敵人意圖全部攤開。
3. **整個世界是同一隻手畫的**：2D 與 3D 都遵守同一套美術規範。不符合規範的素材，就算好看也不收。

**不做的事**（用來擋範圍擴張）：
- 不做 3D 探索、可走動的城鎮或開放世界。第一級只有戰鬥是 3D；要升到第二級，得等垂直切片驗收過後另外決定。
- 不做裝備格與數值養成。
- 不做隨機地圖主線。
- 不做多重難度階梯（A0–A20 這類）。只有兩種難度，開局就能選：「劇情」（敵人 HP −40%）與「標準」。
- 不做「輪迴」或任何沒有劇情理由的隨機模式（違反支柱 1，凍結）。
- 不做配音、不做線上對戰。

## 2. 遊戲循環

```
章節路線圖（手繪 2D 地圖，手工設計節點）
  ├─ 劇情節點：2D 視覺小說式對話，偶有選擇（影響情誼與支線）
  ├─ 戰鬥節點：固定遭遇（3D 戰鬥舞台），打完選 1/3 張新牌
  ├─ 支線節點：選擇性；給法寶、稀有牌或劇情
  ├─ 客棧：休息回血，或花銅錢買牌、刪牌、升級
  └─ 章末 Boss → 下一章
```

- 每章 5–9 個節點，其中戰鬥 4–6 場。路線可以小分岔（例如支線二選一），但主劇情節點固定。
- 牌組、銅錢、法寶、情誼跨章累積。「情誼」是劇情好感，只影響對話、支線與少量獎勵；戰鬥裡的合擊量表另稱「合擊氣」（§4.3），兩者無關。
- 戰後選牌可以跳過（改拿少量銅錢）。

### 2.1 HP、戰敗與重來（防止卡死）
- HP 在同一章內跨戰保留；進入新章與在客棧休息時回滿。昏迷的人戰後回到最大 HP 的 25%。
- 戰敗就從該場戰鬥前重來，不會整局重開。重來時全隊 HP 至少回到 60%，避免殘血進 Boss 只能無限重來。
- 同一場連敗 2 次：提供「這場改用劇情難度」的選項（只影響這一場）。
- 每位角色的牌數下限 8 張，客棧刪牌刪不到下限以下。這樣就算刪光其他牌，任何章節的單人段落（例如第七章開頭只剩逍遙）都還打得下去。
- 自動通關 bot 要驗證「最差牌組也能通關」，而不是看勝率。

### 2.2 牌組隨隊伍變化
- 角色離隊時，他的牌整批移出牌組（含升級），暫存起來；歸隊時整批加回。離隊只發生在劇情節點，不會在戰鬥中途。
- 第一次入隊時給一副依章節預先組好的牌組（張數與強度對齊當時的逍遙），避免後期入隊的阿奴遠弱於累積六章的逍遙。
- 月如身亡後，額外給一次選牌，補回牌組厚度。

**隊伍變化是這個設計的情感引擎**（規則見 §2.2）：
- 角色離隊，他的牌就整批離開牌組；歸隊時整批回來。玩家會一再感受到「少了一個人」。
- **月如之死**：第六章末，她的牌永久移除，只留下一張紀念牌（暫名「月如的長鞭」，是「無主牌」，見 §4.1，效果待設計）。第七章開頭只剩逍遙一人，直到阿奴加入。
- **客串隊友**：巫后只在十年前段入隊。她的小牌組在這段期間洗進共用牌組，段落結束時移出。

**正史裡打不贏也打不輸的戰鬥**（林天南、毒娘子「撐 7 回合」、石長老「勝負皆可」）改成「求生戰」：
- 勝利條件是撐過指定回合數；提前把敵人打倒也算勝利。
- 求生戰沒有戰敗：全員昏迷時直接進入劇情，只是少拿獎勵。

## 4. 戰鬥規則（v1 草案；數字全部是暫定，等垂直切片試玩再調）

### 4.1 基本
- 隊伍最多 3 人**同時在場**，各自有 HP 和護體。這取代舊的主備切換。
- **共用一副牌**：每張牌屬於某位角色，打出時由那位角色出手（3D 舞台上播他的出招動作）。
- 每回合 3 點真氣，抽 5 張，回合結束棄掉手牌。
- 敵人的**意圖永遠攤開**，而且會指明打哪位角色。所以替誰加護體本身就是一個取捨。
- 同一場戰鬥最多 3 名敵人。全員昏迷才算戰敗。

**目標與牌的歸屬**（實作依據）：
| 情況 | 規則 |
|---|---|
| 攻擊牌 | 打出時選一名敵人；全體攻擊不用選 |
| 護體、治療、解除狀態 | 卡面註明「自己」或「任一隊友」。「任一隊友」打出時選人，讓「替誰擋」成為真正的選擇 |
| 意圖指定的角色已經昏迷 | 改打最左邊還清醒的隊友，畫面上的意圖同步更新 |
| 角色昏迷時 | 他在手牌、抽牌堆、棄牌堆的牌全部變成「心念」：0 費、打出後抽 1 張並消耗；不算連鎖、不算合擊氣。被復活時，未消耗的心念變回原牌 |
| 昏迷的戰後 HP | 回到最大 HP 的 25%（§2.1） |
| 無主牌（紀念牌、偷來的牌、部分道具牌） | 由「當下 HP 最高的清醒隊員」出手；3D 舞台播通用施法動作 |
| 客串隊友的牌 | 段落期間洗進共用牌組，段落結束時移出（§3） |

### 4.2 五靈
- 仙術牌與敵人都可以帶屬性：**風、雷、水、火、土**。
- **相剋（仙劍一）**：風剋雷、雷剋水、水剋火、火剋土、土剋風。
  - 依據：百度「五靈」詞條所載的仙劍一循環，且與遊戲資料中七神龍的抗性表吻合（例如風神龍對土無抗性）。仙劍三、六的循環與此不同，不採用。
  - 仙劍一原作沒有獨立的相剋倍率，而是每個敵人各有五靈抗性；本作把它簡化成固定的相剋規則，讓玩家看得懂。
  - 剋制命中：傷害 ×1.5，並給敵人 1 層「破勢」。
  - 破勢累積到門檻：一般敵人**下一個意圖被取消**；Boss 不取消，改成**下一個意圖減半**（傷害與效果都減半）。觸發後破勢歸零。
  - **防止鎖死**：每個敵人每回合最多觸發一次破勢；每觸發一次，該敵人的門檻 +1（一般敵人從 2 起跳，Boss 從 3 起跳）。
  - 本作沒有「暈眩」狀態：控場只有破勢一種，避免兩套控場疊在一起。
  - 被剋：傷害 ×0.5。
- **屬性對照**（把正史的名稱收斂到五靈）：炎→火、冰→水；毒與金不算五靈屬性（七神龍裡的毒龍、金龍視為無屬性，各用招牌機制考驗玩家）。
- **相生連鎖（本作原創）**：風→火→雷→土→水→風。
  - 仙劍一沒有相生設定，這個順序是依五行「相生、相剋互為隔位」的結構，從上面的相剋循環推導出來的，屬於原創規則。
  - 同一回合依相生順序出仙術，每接一環連鎖 +1；之後的仙術**傷害與護體**各 +連鎖數。連鎖不影響抽牌、真氣、破勢層數。
  - 中斷就歸零。
  - 畫面上放一個「五靈輪」，標出下一環該接的屬性。
- **傷害計算順序**（卡面顯示的預測值照同一個順序算）：
  基礎值 + 氣勢 + 連鎖 → × 相剋（1.5 或 0.5）→ × 弱化（攻方 ×0.75）→ × 破綻（守方 ×1.5）→ 無條件捨去 → 先扣護體，再扣 HP。
- **五靈牌的分布**：
  - 逍遙：用符咒與劍訣帶五靈屬性（序章只有他一人，必須能教相剋）。
  - 靈兒：正史一開始就會風、雷、炎、土、冰五咒，五系俱全，是連鎖主力。
  - 阿奴：巫術帶屬性。
  - 月如：以鞭、劍的連段為主，只有少數兵器或事件牌帶屬性，不強求。
- 設計意圖：每回合都是一道看得見的排序題，「先出哪張」比「出不出」更重要。

### 4.3 角色：四種解法
| 角色 | 專屬動作 | 打法 | 依據 |
|---|---|---|---|
| 李逍遙 | **偷**：從敵人身上偷出道具或牌 | 御劍速攻、連擊，劍可以離手飛出 | 御劍術、萬劍訣；飛龍探雲手 |
| 趙靈兒 | **咒**：五靈仙術主力，負責接連鎖 | 慢熱，後期爆發、治療 | 女媧後裔、靈族神術 |
| 林月如 | **連**：連段與反擊 | 近戰壓制、反擊流 | 鞭法、劍術 |
| 阿奴 | **蠱**：養蠱蟲當作場上單位 | 引擎型；蠱、驅鬼、攝魂、巫醫都有，不是純毒師 | 苗疆巫術 |

- **合擊（照正史規則改編）**：
  - 正史的合擊不是固定雙人技，而是「由誰發動就用誰的招式，全隊一起出手」：逍遙＝合體氣功、靈兒＝爆炸、月如＝弦月斬、阿奴＝天女散花、巫后＝爆炸蠱。
  - 條件：在場至少 2 人，而且沒有人昏迷或虛弱（HP 低於 20%）。
  - 代價：全隊扣 HP，並結束本回合。
  - 本作：
    - 不同角色的牌交替打出會累積「合擊氣」（戰鬥內量表，戰鬥結束歸零）。
    - 合擊氣滿時，**最後一張打出的牌是誰的，發動者就是誰**，他的合擊牌加入手牌。
    - 打出合擊：全隊各扣最大 HP 的 10%（最低留 1，不會因此昏迷），並結束本回合。
    - 合擊在 3D 舞台上有專屬運鏡，全隊一起出招。
  - 帶靈珠時合擊會變成風神、雷神、雪妖、火神、山神等招式（正史設定）。本作不做靈珠系統（避免變成裝備格），凍結。
- **牌數**：
  - 每位主角約 22 張可收集的牌，主角共約 88 張。
  - 其餘：巫后 6 張、合擊 5 張、無主牌（紀念牌、偷來的牌、道具牌）約 15 張。
  - 全遊戲約 115 張。
  - 每張主角牌都要對得上一個正史招式或事件；無主牌對得上正史道具。
- **動作量**：每位角色做 5–8 種共用出招動作（例如劈、刺、施法、護身、受擊），牌只指定用哪一種，不為每張牌客製。動作可加速（1.5×）或略過。

### 4.4 效果詞彙（≤ 25 種，新增要先改這張表）
| 類別 | 效果 |
|---|---|
| 基本 | `damage` `damage_all` `multi_hit`（連擊）`block` `heal` `draw` `discard` `gain_qi` `scry`（觀察牌堆頂） |
| 狀態 | `apply`（弱化、破綻、中毒、破勢）`cleanse` `strength`（氣勢） |
| 角色招牌 | `steal`（偷：先顯示可偷的東西再出手）`counter`（月如：本回合受擊時反擊）`summon`（阿奴的蠱；敵人召喚也用它）`fly_sword`（逍遙：劍離手，下回合開始時對指定敵人再打一次） |
| 牌流 | `exhaust` `retain` `upgrade_in_combat` |
| 隊伍 | `revive` `combo_gauge`（加合擊氣） |
| 場地 | `field`（Boss 場地狀態：水域、血池；有自己的耐久值，被打破才解除效果） |

共 24 種。屬性（`element`）是卡牌欄位，不算效果。

狀態只有 6 種：護體、氣勢、弱化、破綻（易傷）、中毒、破勢。

**場上單位上限**：蠱蟲和召喚物用小型 2D 圖示表示，不佔 3D 角色名額（§6.4）。

### 4.5 敵人設計規則
- 每種敵人**只有一個招牌機制**，意圖文字一眼就看得懂。
- Boss 機制取材正史：
  - 水魔獸（十年前南詔、水底迷宮）：在水中殺不死、會復活，要先破水域。巫后同場作戰。
  - 赤鬼王（血池）：先斷血池再打本體。
  - 鎮獄明王（鎖妖塔）：身上有 9 顆玉菩提，可以用逍遙的「偷」偷走。
  - 蛇妖男 → 狐狸精（隱龍窟）：Boss 接續，打倒一隻、下一隻登場。
  - 七神龍（鎖妖塔）：風、土、毒、雷、冰、金、火七隻，用來考驗五靈相剋（屬性對照見 §4.2）。
- 「求生戰」：林天南、毒娘子、石長老（規則見 §3）。

## 5. 故事與文字

- 忠於正史的事件與人物關係，但**台詞全部重寫**，不照抄原作劇本。
- 語氣照原作節奏：前段詼諧，後段悲劇。
- 呈現：2D 視覺小說式。主角各畫約 6 種表情（平常、笑、怒、驚、哀、決意），配角 2–3 種。
- 篇幅：全劇本約 3–4 萬字。
- 劇情裡的選擇只影響情誼、支線與小獎勵，不分歧結局。主線忠於正史。
- 只做繁體中文；所有文字放在外部資料檔，不寫死在程式裡。

## 6. 美術方向：B 國風厚塗（2D）＋同風格的 3D 戰鬥

### 6.1 風格定義
- **2D**（劇情立繪、卡圖、章節地圖、戰鬥遠景）：半寫實國風厚塗，有電影感的柔光，色彩飽和但和諧。基準圖是 `docs/redesign/art_direction/B_painterly_*.png`。
- **3D**（戰鬥舞台的角色、敵人、近景道具）：用著色器把模型「畫」成同一種風格。
  - **著色**：分階明暗（3 階）、輪廓光。描邊先不做（模型外殼法會讓面數與繪製次數翻倍），等效能實測有餘裕再評估。
  - **後製**：柔光暈與暗角，之後加每章調色 LUT。手機上可整組關閉（畫質選項）。
  - **遠景**：手繪背景投影到簡單的 3D 幾何上（已在原型實作：`Xiaoyao/src/stage/backdrop.ts`）。
- **3D 與 2D 的分工**（審閱後修訂）：
  - **3D 模型**：五位可操作角色（逍遙、靈兒、月如、阿奴、巫后），加上人形的一般敵人與人形 Boss。
  - **2D 立繪立在 3D 舞台上**：非人形角色（蛇妖、七神龍、金翅鳳凰、火眼麒麟、水魔獸、五毒巨蠍、樹妖等），以及 3D 綁骨做不好的長裙長袍角色。作法沿用舊專案已驗證過的「立繪板子＋真實陰影」，再加上簡單的呼吸、受擊、衝刺位移。
  - 理由：AccuRIG、Mixamo 只支援雙足人形；非人形逐隻手工綁骨的成本遠超本專案產能。
- **同一張臉原則**：每位角色先定一份 2D 角色設定表（正、側、背），3D 模型和 2D 立繪都以它為準。
  - 維持同一張臉的做法：先用同一份設定表當參考圖生成（img2img 或參考圖控制），做不到時才考慮雲端訓練角色 LoRA（本機 6GB 顯存不夠訓練 Z-Image 的 LoRA）。
  - 設定表另出一版「無光影平塗」給 3D 投影貼圖用，避免厚塗稿的明暗烘進貼圖，和著色器的光照疊成雙重光影。

### 6.2 不論 2D 或 3D 都要遵守
- **調色**：每章一組主色，例如序章青綠、仙靈島水藍月白、鎖妖塔墨紫、南詔赭紅。五靈固定配色：風青、雷紫、水藍、火朱、土赭。
- **剪影**：以 1280×720 的 CSS 像素為基準，角色在戰鬥畫面約 200px 高時，剪影仍要認得出是誰（髮型、兵器、披掛）。
- **造型改動上限**：以仙劍一原版造型為準，只允許為了 3D 綁骨做小幅調整（例如長披掛縮短、袖口收窄）；同樣的調整 2D 立繪也要跟著做。
- **五靈不能只靠顏色辨識**：每系另有圖示與文字（風青和水藍、火朱和土赭容易混淆）。
- **UI**：古籍、卷軸、印章的質感，費用畫成印章。字型用霞鶩文楷 LXGW WenKai（標題、卡名）和 Noto Serif TC（內文），兩者都是開源授權。
  - 中文字型很大（霞鶩文楷 TC 每個字重約 12–13 MB）。打包時要從劇本與卡牌抽出用到的字做子集，內容測試要驗證沒有缺字。
  - 介面精緻度的參考對象是 settlecoast.com。
- **卡框**：只設計一次，所有卡牌共用。
- **音樂**：原作音樂有版權，改用原創或免版稅的古琴、笛子、簫配樂。

### 6.3 製作流程（原型已跑通，2026-10-04）
1. **2D 設定稿**：本機 ComfyUI + Z-Image Turbo（`SwordCard/tools/comfyui/zimage_txt2img.py`）出三視角設定表。
   - 姿勢用 A-pose，雙手空著、不拿兵器（兵器由管線另外做；拿在手上會黏進網格）。
   - 袖子和身體分開，長披掛縮短。
2. **切圖**：rembg（birefnet-general）去背、切成 front／right／back 三張，左側由右側鏡像；`Xiaoyao/tools/art/pad_views.py` 把邊緣顏色外擴，避免投影貼圖沾到白底。
3. **3D 形體**：本機 Hunyuan3D-2mv（`SwordCard/tools/comfyui/hunyuan3d_mv.py`，約 2–3 分鐘一隻）；品質不夠的改用雲端服務的私有模式（需使用者自己登入）。
4. **後製**：`Xiaoyao/tools/blender/build_character.py` 依 `rig.json` 一次做完：
   - 清碎塊、體素重建、減面到約 1.5 萬面
   - 四視角投影貼圖（含遮擋判斷）
   - 依 `joints` 建骨架，bone heat 綁權重（失敗時改用距離加權）
   - 兵器骨與兵器模型
   - 依 `poses`、`actions` 做多關鍵影格動作
   - 匯出 GLB
5. **通用動作**：之後要嘗試 AccuRIG 或 Mixamo 的現成動作庫，重定向後在 Blender 裡烘焙；目前用管線內的手調關鍵影格。
6. **壓縮**：GLB 經 gltf-transform 壓縮（網格 meshopt、貼圖 KTX2）。解碼器要自己放進專案，不從外部 CDN 下載（離線 App 才能用）。
7. **風格關卡**：每個素材進遊戲前都要過檢查清單（線條、調色、剪影、比例、AI 破綻）。不過就重做，不湊合。

### 6.4 效能與下載預算（手機為準）
| 項目 | 上限 |
|---|---|
| 每個 3D 角色或敵人 | 3 萬三角面、1 張 2048 貼圖（KTX2）、≤ 70 根骨頭（容得下 Mixamo 的 65 根） |
| 同場 | 6 個 3D 角色（3 人＋3 敵）、總計 20 萬三角面、≤ 150 次繪製呼叫；蠱蟲與召喚物用 2D 圖示，不算在內 |
| 燈光 | 1 盞投影方向光＋環境光 |
| 渲染解析度 | 裝置像素比上限 1.5（手機 DPR 3 是最大的效能殺手）；反鋸齒用 MSAA，手機可關 |
| 幀率 | 參考機型 ≥ 30 fps，桌機 60 fps。參考機型由使用者指定一支實際手機 |
| 下載 | 首次進入 ≤ 30 MB（含子集化字型）；各章素材在進入該章時才載入 |

原型實測（2026-10-04）：李逍遙約 2.7 萬三角面、1.7 MB；山賊約 2.8 萬三角面、1.9 MB。

## 7. 平台與架構

### 7.1 技術選擇
| 用途 | 選擇 | 授權 |
|---|---|---|
| 語言、建置 | TypeScript、Vite | MIT |
| 介面 | React | MIT |
| 3D | React Three Fiber＋drei（Three.js） | MIT |
| 後製 | postprocessing | Zlib |
| 狀態驗證 | zod | MIT |
| 音效 | Howler.js | MIT |
| 測試 | Vitest、Playwright | MIT／Apache-2.0 |
| 打包 | Capacitor（Android）；Windows 先用瀏覽器或 PWA，需要時再評估 Tauri | MIT |

為什麼用網頁：
- 遊戲大部分時間在看卡牌介面和劇情對話，這正是網頁最強的地方。
- AI 寫 TypeScript 的品質明顯較好，型別系統能擋掉舊專案最常見的 bug。
- 手機只要開網址就能實測；分享給朋友也只要一個網址。
- 第一級的 3D 需求（6 個骨架角色、鏡頭、特效、後製）在 Three.js 都是成熟用法。

已知限制與坑：
- 沒有視覺化場景編輯器，場景要用程式擺。
- 手機效能餘裕比原生 App 小，必須守 §6.4 的預算。
- Android 打包版（Capacitor 的 WebView）有開發者回報比 Chrome App 慢，**驗收要在打包版上做**，不能只看瀏覽器。
- Windows 打包版（Tauri 的 WebView2）在雙顯卡筆電上預設跑內顯，目前沒有官方方法強制用獨顯；這也是 Windows 先用瀏覽器或 PWA 的原因。
- three.js 從 r163 起只支援 WebGL2。
- 若之後要升到第二級（可走動的 3D 城鎮），要重新評估平台。

### 7.2 分層
```
src/
  core/          純邏輯：GameState、指令（PlayCard / EndTurn / ChooseReward…）、
                 reducer、事件、種子化隨機數。不碰 DOM 和 Three.js。同一個種子加同一組輸入，結果永遠相同。
  content/       卡牌、敵人、章節、對話：用資料檔描述（JSON 或 YAML），zod 做 schema 驗證
  ui/            React 畫面：卡牌、劇情、地圖、選單
  stage/         3D 戰鬥舞台：React Three Fiber。訂閱 core 事件、播動作與特效佇列，永遠不直接改遊戲狀態
  platform/      存檔（序列化 GameState＋版本號＋遷移）、音訊、輸入（滑鼠／觸控）
tests/
  core/          每種效果的單元測試、整場戰鬥重播比對、存檔遷移
  content/       內容檢查：每張牌有圖、每個劇情節點都走得到、文字沒有超出卡框、字型子集不缺字、
                 素材預算（面數、骨頭數、貼圖尺寸，照 §6.4）
  e2e/           Playwright：介面截圖比對（桌面＋手機尺寸）；3D 舞台只驗載入與事件，不比對像素
  bot/           自動通關：驗「最差牌組也能通關」與經濟曲線；窮舉單回合出牌順序，找出能鎖死敵人的組合
```
- Playwright 跑的是桌面 Chromium，測不到 Android WebView 和真實手機 GPU。每個階段的驗收都要在參考機型的打包版上手動跑一次。

### 7.3 平台差異
- **存檔**：
  - 所有平台統一用 IndexedDB，另提供「匯出／匯入存檔」做備份，避免三套存檔後端。
  - 每個節點完成時自動存檔；戰鬥中存「隨機種子＋指令序列」，讀檔時重播回同一個狀態；App 切到背景時立刻存檔。
  - 3 個存檔欄位。存檔帶版本號，改格式時寫遷移並加測試。
- **音效**：手機瀏覽器禁止自動播放，第一次觸控後才啟動音訊。
- **輸入**：滑鼠和觸控用同一套手勢（拖曳出牌、長按看說明），不依賴滑鼠懸停。
- **橫向**：Android Chrome 只有全螢幕或安裝成 App 時才能鎖定橫向；手機直拿時顯示「請轉成橫向」。
- **Android 返回鍵**：開啟中的視窗先關閉，戰鬥中開暫停選單，不直接離開。

### 7.4 紀律（吸取舊專案教訓）
- 程式碼單一檔案超過 400 行就拆（資料檔與劇本不受限）。
- 狀態只能透過 reducer 改。
- CI 綠燈才能合併。
- 新系統必須寫進本文件，並對應到某根支柱。
- 已知 bug 超過 10 個時，凍結新功能，先修 bug。

**停損**：任一項經兩輪修正（每輪最多 1 週）仍不過，就把 3D 範圍縮小：先改成「只有主角群 3D」，還不行就整個退回 2D 國風厚塗。退回 2D 時舞台仍用 Three.js（手繪遠景投影＋2D 立繪板子），故事、戰鬥設計、介面都不受影響。

## 12. 正史考據摘要（2026-10-03）

查證方式：每項至少兩個來源互相印證；只有單一來源的標「單一來源」。

- **李大娘**：逍遙的**嬸嬸**（叔父李三省之妻孫嵐，人稱「鐵掌飛鳳」），不是外婆。舊 `PAL1_CANON.md` 寫錯。
- **隊伍**：同時上場最多 3 人。可操作角色只有逍遙、靈兒、月如、阿奴與巫后（只在十年前段）。酒劍仙、劉晉元從未入隊；唐鈺只是大理的路人 NPC（單一來源）。
- **順序與隊伍變化**：見 §3。修正點：
  - 十里坡在第一次仙靈島**之後**。
  - 靈兒首次入隊是在餘杭客棧救出她時，不是在仙靈島。
  - 仙靈島沒有 Boss。
  - 將軍塚是殭屍王，赤鬼王在血池。
  - 阿奴在靈山神木林入隊，不是大理。
  - 終戰在南詔王宮；「拜月教壇」不是仙劍一的地名。
  - DOS 原版只打拜月教主，他與水魔獸融合是劇情，不是戰鬥。
  - 阿奴重新入隊的時點，兩份攻略說法不一（女媧神廟或試煉窟外）。
- **合擊**：由發動者決定招式、全隊參與（見 §4.3）。
- **五靈**：每個敵人有五靈、毒、物理抗性。法術靠升級學會，不是裝備靈珠；靈珠會改變合擊招式。相剋循環見 §4.2（單一文字來源，但與七神龍抗性吻合）。
- **武器**：
  - 逍遙：劍（七星劍；最終無塵劍、太極劍）。
  - 靈兒：雙劍、天蛇杖。
  - 月如：鞭為主（金蛇鞭），也能用劍和刀（鳳鳴刀、越女劍）。
  - 阿奴：刀與杖（玄冥寶刀、巫月神刀、冥蛇杖）。
- **師承**：酒劍仙在十里坡山神廟傳授御劍術；冰心訣、飛龍探雲手來自逍遙父母留下的手卷。
