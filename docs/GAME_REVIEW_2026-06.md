# SwordCard 遊玩度總體檢報告（2026-06-10）

> 範圍：美術、排版/UI、風格、遊戲平衡、故事性、玩法、未來發展。
> 依據：全程式碼盤點（161 卡 / 83 敵 / 71 遺物 / 37 藥 / 34 事件 / 8 幕）、

## 0. 總評

**一句話：機制深度已是商業級 demo 水準，現在的短板是「第一眼觀感」與「一條把 8 幕串起來的故事線」。**

| 維度 | 評分 (10) | 一句話 |
|---|---|---|
| 玩法系統 | 8.5 | StS 骨架＋組隊切換＋多敵召喚＋等級解卡，機制密度超過多數同類獨立作 |
| 遊戲平衡 | 7.5 | 測試基建一流（四層 baseline＋AI 驅動器），但角色間中段勝率 3%–83% 差距過大 |
| 美術 | 7.5 | 量已達 95%（167 卡圖、60 敵肖像、8 幕背景），質的整合（標題字、選單質感）未完成 |
| 排版/UI | 6 | 功能齊全但「資訊密度高、視覺層級弱」：選單按鈕迷你、地圖空曠、卡片字牆 |
| 風格 | 8 | 水墨＋暖金方向明確且一致，音樂音效已落檔；差最後一層「裝裱」 |
| 故事性 | 6.5 | 奇遇樹＋長尾旗標做得好，但 8 幕之間沒有敘事主線、Boss 倒下即黑屏 |
| 長期黏著 | 5 | 無 meta-progression：打完一輪後「再開一局的理由」只剩 Ascension 爬層 |

## 1. 玩法（Gameplay）

### 優點
- **機制堆疊有層次**：能量/格擋/中毒/虛弱/破綻是 StS 驗證過的底盤，其上疊了
  組隊主備制（切人 tempo 決策）、多敵+AOE+召喚（目標選擇決策）、藥品（爆發窗口決策）、
  stun/silence/berserk 控制系（針對性反制）。每層都有真決策，不是裝飾。
- **角色流派分化清楚**：劍流（李）/ 五靈神術（趙）/ 反擊連擊（林）/ 毒流（阿奴），
  passive、起手 12 張、reward_pool 38–49 張各自成體系。
- **等級系統（Lv1–50 解卡）**是同類遊戲少見的 run 內成長軸，
  「打 Boss 150xp → 解 rare 卡」給了戰鬥獎勵以外的第二條期待線。
- **奇遇已完成取捨化改造**：34/34 事件分支樹、賭注、build/血量/旗標檢定、長尾回訪閉環。

### 缺點與改善
| # | 問題 | 改善方案 |
|---|---|---|
| 1 | **8 幕一輪太長**。StS 3 幕 ≈ 45–60 分鐘；本作 8 幕 × 9–11 層，單輪估 2.5 小時以上，手機場景下幾乎不可能一口氣打完 | 短期：確認單幕節奏（每幕 9–11 層偏多，可砍到 7–8 層）；中期：提供「短征模式」（3 幕速通，獨立 baseline）；存檔隨時續玩已有，但「一輪的心理負擔」仍在 |
| 2 | **地圖節點決策薄**：截圖可見每層 4 個節點但路徑分歧少、節點類型以戰鬥為主（~60-70%），玩家「選路」的意義不大 | 提高 event/shop/rest/treasure 出現比例與路徑差異（左路富險、右路貧穩）；節點先行揭示獎勵提示（如「此戰掉藥」） |
| 3 | **切人成本太便宜**：首切免費、再切 1 能量，主備制容易退化成「誰血多誰上」 | 給切人加正向 hook：切入角色獲 2 護體（鼓勵主動運營）或部分敵人懲罰切人（盯防 intent），讓切人是「策略」而非「規避」 |
| 4 | **藥品偏同質**：37 種裡大量是「回血/加能量/打傷害」的數值階梯 | 後續新增藥品往「改規則」走（本回合卡牌不耗能量 / 複製下一張卡 / 本場 weak 變 power），數值階梯不再加 |
| 5 | **通用卡 21 張存在感低**（無門卡多為基礎動作） | 讓通用卡承擔「跨流派膠水」角色：明確 2–3 張支援毒流、2–3 張支援疊攻的中性卡，獎勵池抽到時才有「拿不拿」的張力 |

## 2. 遊戲平衡

### 優點
- **測試基建是本專案最強資產**：四層 baseline（基礎/中段/升級/分級進程）× 4 角色
  ＋ ±15pp 容差 regression 把門 ＋ AI 平衡驅動器（真 BattleController、可倒帶、可混合委派）。
  多數商業卡牌遊戲都沒有這種自動化平衡防線。
- 2026-06 的「敵傷 +15%、經濟回拉」方向正確（向 StS 的「困難旅途」靠攏）。

### 缺點與改善
| # | 問題 | 改善方案 |
|---|---|---|
| 1 | **角色中段勝率撕裂：李 3% / 趙 27% / 林 40% / 阿奴 83%**（起始牌組 vs 蜈蚣大王 10 回合）。即使隨機 AI 有失真，27 倍差距說明李逍遙起手節奏遠弱於阿奴的開場 5 層毒 | 用 AI 驅動器親手各打 2–3 場李/阿奴 run 對照；方向上：給李的「第一張攻擊 -1 費」passive 加值（例如改「每回合第一張攻擊 -1 費」），或下修阿奴開場毒 5→3 |
| 2 | **升級後中段全員 80–100%**：升級價值過猛（3%→80% 是 26 倍跳躍），「找到升級」比「選對卡」重要 | 壓平升級曲線：基礎值略升、升級增幅略降，讓 build 決策權重回到選牌 |
| 3 | **多人隊伍無 baseline**：隨機 AI 不切人，2/3 人隊實際強度未知（設計預估 1.5–2×單人） | 在 AI 驅動器加「簡單切人 policy」（active 瀕死即切）後補 2 人/3 人 baseline |
| 4 | **經濟未壓力測試**：除卡 75、藥 40/65/95，但金錢收入 8 幕累積下是否通膨未驗證 | AI 驅動器跑一輪全程記錄 gold 曲線；目標：玩家在幕 4–6 應該常態「想買買不起」 |

## 3. 美術

### 優點
- **量體已達 95%**：167 卡圖、60 敵肖像、37 藥圖、33 事件插畫、8 幕戰鬥背景、
  14 首 BGM ＋ 13 個 SFX（含 crossfade 與防疊放）。對個人專案而言完成度驚人。
- 水墨基調統一（主選單山水、地圖水墨卷、事件插畫同風）。

### 缺點與改善
| # | 問題 | 改善方案（多數已登記 ART_TODO） |
|---|---|---|
| 1 | **主選單沒有遊戲標題**：截圖中只有山水＋一疊按鈕，玩家第一眼不知道遊戲叫什麼。是目前最傷「第一印象」的單點 | 補 `title_swordcard.png` 毛筆題字（ART_TODO 已列）——**建議列為美術最高優先**，高於 Boss 劇情圖 |
| 2 | **地圖節點視覺太素**：截圖中節點是細線＋小圖示，水墨底圖反而吃掉節點對比，路徑感弱 | 節點放大 1.5×、加描邊光暈；已走過路徑改墨色實線、未走虛線；當前位置加呼吸動畫 |
| 3 | **9 張 Boss 擊敗劇情圖未補**：8 幕打完 Boss 直接跳結算，情緒沒有出口 | 按 ART_TODO 優先補 `baiyue_lord`（終幕）；過渡方案：先用「幕背景＋詩句字卡」頂替，成本近零 |
| 4 | **AI 生圖風格漂移風險**：卡圖 167 張多批次生成，水墨濃淡、線條粗細存在批間差 | 建一張「全卡圖網格 contact sheet」工具圖（程式拼接即可），肉眼掃一遍挑出最違和的 10 張重生成 |
| 5 | 選單水墨裝裱 5 件套（宣紙紋/卷軸框/筆觸分隔線/角落墨紋）未落地 | 已在 ART_TODO；落地後選單質感預期跳一級 |

## 4. 排版 / UI

### 優點
- UI 全程式碼建構＋UIFactory/ThemeColors/CardFormat 三層分工，改版成本低。
- 行動端細節到位：返回鍵、safe area、觸控長按預覽、拖拉出牌、PopupPanel 替代 tooltip。
- 39 種出牌動畫＋DamagePopup，戰鬥回饋不貧乏。

### 缺點與改善（依截圖逐畫面）
| 畫面 | 問題 | 改善方案 |
|---|---|---|
| 主選單 | 按鈕擠在中下方一個小框內，字級小、視覺重心懸空；美術佔 80% 畫面但 UI 像浮貼 | 按鈕列加寬（≥260px）、字級 ≥20、垂直間距拉開；或改「右側豎排選單＋左側留白給山水」的構圖，讓 UI 與畫共生 |
| 角色選擇 | 右側說明是整面小字牆（出身/武器/機制/牌組全擠一欄） | 資訊分層：上半「一句話定位＋難度星級」，下半摺疊詳情；牌組預覽改可點開 |
| 地圖 | 節點小、線細、留白過多，資訊層級（當前/可去/已過）靠顏色微差 | 同美術 #2；另把右上角圖例改成首次進入的一次性提示，平時收起 |
| 戰鬥 | 卡片字多且字級小（效果文字 + 數值擠在 ~140px 寬卡上）；畫面中央大片空，敵我兩側貼邊 | 卡面改「圖 60% + 一行效果摘要」，完整文字留給長按預覽（已有此機制，正好分流）；敵我向中央收 10–15%，讓對峙感出來 |
| 整體 | 字級系統未統一（12–28 隨處可見），小螢幕可讀性存疑 | 定義 4 級字階（標題 28 / 區題 20 / 正文 16 / 註記 13）寫進 UIFactory，全 UI 收斂到字階上 |

> 驗證方式：每項改完用 `render_report.gd` / `render_event.gd` 截圖肉眼比對（CLAUDE.md 既定流程）。

## 6. 故事性

### 優點
- 奇遇重設計後是目前敘事最強的部位：分支樹、角色限定分歧、長尾旗標回訪
  （放走狐女→鬼林引路；酒館打聽→清泉遭伏）、PAL1 名場面 6 個。
- PAL1_CANON.md 把正史當資料庫管理，新內容不會跑調。

### 缺點與改善
| # | 問題 | 改善方案 |
|---|---|---|
| 1 | **8 幕之間沒有敘事主線**：餘杭→仙靈島→…→水底迷宮是地點串燒，玩家不知道「我為什麼一路打過去」 | 最低成本方案：每幕開場 1 張字卡（2–3 句，幕名＋目的，如「黑苗血洗仙靈島，林家堡來信求援…」）＋幕末 Boss 倒下 1 句收束。8 幕 × 2 段文字即可建立「旅程感」，不需要過場動畫 |
| 2 | **Boss 戰勝利零敘事**：打倒拜月教主與打倒山賊頭目的結算畫面相同 | 同美術 #3：Boss 劇情圖＋一段定場文字；終幕 Boss 另做簡易結局頁（依角色/旗標變 2–3 種結語，event_flags 基建現成） |
| 3 | **隊伍角色之間零互動**：3 人同行但從不交談 | 低成本高回報：切人/倒下/勝利時 1 行隊友台詞（依「在場隊友組合」選 banter 池）；李＋月如、靈兒＋阿奴各寫 10 句就夠玩家會心 |
| 4 | 事件旗標的回收點還少（雙向示範閉環各 1 條） | 按 EVENT_REDESIGN_PLAN 既定方向持續擴編人物回訪線（非阻塞，已列） |

## 7. 長期黏著與未來發展

### 現況
跨 run 持久化只有 Bestiary（統計）＋ Ascension 解鎖（A0–A20）。
**沒有任何 meta-progression**：無解鎖卡、無解鎖角色、無成就。種子分享/每日挑戰已有但無紀錄保存。

### 發展路線圖（按投入/回報排序）

**近期（1–2 週量級）——把「再開一局」的理由補上**
1. **戰績檔案頁**：每輪結束記錄（角色/層數/死因/用過的牌組）存 `user://history.cfg`，
   主選單加「征途錄」。成本低，立刻給玩家「我在進步」的證據。
2. **成就 30 條**（用 Bestiary/Ascension/event_flags 現成資料判定：全角通關、A5 通關、
   毒流一場 50 毒、無傷過 Boss…），成就頁複用圖鑑 UI。
3. **每日挑戰加榜**：本地最佳紀錄即可（同 seed 重打比層數/剩餘 HP），不需伺服器。

**中期（1–2 月量級）——內容寬度**
4. 第 5 位角色（PAL1 卡司還有：劉晉元/彩依 雙生妖姬流、或酒劍仙 醉拳流）——
   現有資料管線（CharacterData＋reward_pool＋baseline）可直接吃新角色。
5. 詛咒系統擴編（現 6 種）＋「帶詛咒換大利」的稀有事件，配合 A10 起手詛咒形成體系。
6. Boss 劇情圖 + 幕間字卡（見故事性 #1#2）。

**遠期（發佈向）**
7. **平台**：Android 已在目標內；桌面端可評估 itch.io 先行（免費 demo 收回饋）→ Steam。
   注意：仙劍同人定位，**商業化前須確認 IP 邊界**（目前「私人粉絲向原型」定位安全，
   公開發佈建議改名＋去 IP 化或維持非商業）。
8. 本地化：簡中近乎免費（OpenCC 轉換＋人工過一遍）；英文需重寫卡名語感，成本高，後置。
9. 雲存檔/統計遙測（匿名勝率回傳）讓平衡調整有真人數據，補隨機 AI 的失真。
